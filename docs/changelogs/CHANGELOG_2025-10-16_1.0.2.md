# Changelog - 2025-10-16 - Version 1.0.2

**Release Date**: October 16, 2025
**Previous Version**: 1.0.1 (Documentation suite)
**Current Version**: 1.0.2

---

## Summary

Launcher enhancement: Integrated RP setup functionality directly into the launcher. Users can now create new RPs without running a separate setup script. Streamlined workflow with interactive menus for RP creation with template selection.

---

## Added

### Launcher Setup Integration

**`launch_rp_tui.py` - Merged Setup Functionality** (ENHANCED)

Integrated complete RP setup workflow directly into the launcher:

**New Functions Added**:
- `copy_template(template_name, dest_dir, rp_name)` - Copies template files from starter packs to new RP directories
- `create_new_rp(base_dir)` - Interactive setup wizard for creating new RPs with template selection
- `print_success_message(rp_dir, rp_name)` - Success banner showing new RP creation and next steps

**New Imports**:
- `from src.initialize_rp import RPInitializer` - RP initialization system
- `import shutil` - File copying utilities

**Enhanced Main Workflow**:

1. **No RPs Exist**:
   - User prompted: "Would you like to create a new RP?"
   - Can create RP directly from launcher
   - New RP auto-launches after creation

2. **Multiple RPs Exist**:
   - Menu now includes "➕ Create new RP" option
   - Users can create from folder selection menu
   - Seamless: select option → create → launch

3. **Single RP**:
   - Auto-selects and launches as before
   - No changes to existing workflow

**Interactive Setup Flow**:
```
Create New RP
├── Prompt for RP name
├── Check if already exists
├── Select template (minimal, fantasy_adventure, etc.)
├── Initialize directory structure (via RPInitializer)
├── Copy template files to new RP
├── Display success message with next steps
└── Auto-launch new RP
```

**Updated Functions**:
- `select_rp_folder(rp_folders, base_dir)` - Now accepts `base_dir` parameter, includes "Create new RP" option
- `main()` - Updated to handle:
  - Creating RP when none exist
  - Passing `base_dir` to folder selection
  - Handling new RP creation result

## Changed

### Launcher Folder Selection Logic

**`select_rp_folder()` Function Signature** (UPDATED)

Changed from:
```python
def select_rp_folder(rp_folders):
```

Changed to:
```python
def select_rp_folder(rp_folders, base_dir):
```

**Rationale**: Required to access RPs directory and base_dir for new RP creation

**Menu Display** (UPDATED):
- Added "➕ Create new RP" option below existing folders
- Option appears as: `{len(rp_folders) + 1}. ➕ Create new RP`
- Users can select this option to create new RP interactively

### Main Entry Point Logic

**`main()` Function** (UPDATED)

Updated to handle RP creation workflow:

1. **No RPs Found** (lines 550-564):
   - Previous: Exited with error
   - Now: Prompts user to create new RP
   - If user accepts: Calls `create_new_rp(base_dir)`
   - If user declines: Exits gracefully

2. **Multiple RPs** (lines 569-576):
   - Previous: Showed menu only
   - Now: Menu includes "Create new RP" option
   - Calls `select_rp_folder(rp_folders, base_dir)`

## User Experience Improvements

### Workflow Simplification

**Before v1.0.2**:
1. User runs `python setup/quick_setup.py "RP Name"`
2. Script creates RP
3. User runs `python launch_rp_tui.py`
4. Launcher starts existing RP

**After v1.0.2**:
1. User runs `python launch_rp_tui.py`
2. If no RPs exist: Launcher offers to create one
3. If multiple RPs: Launcher shows option to create one
4. Seamless: Create → Launch in one session

### First-Time User Experience

When no RPs exist:
```
Error: No RP folders found.

Would you like to create a new RP?
Create new RP? (y/n): y

[Enters RP creation workflow]
[New RP created and auto-launched]
```

### Menu Experience

When multiple RPs exist:
```
Available RP folders:
  1. Campaign One
  2. Campaign Two
  3. ➕ Create new RP

Select an RP folder (enter number): 3
```

## Technical Details

### Integration with Existing Systems

**RPInitializer Integration**:
- `create_new_rp()` uses `RPInitializer` to initialize directory structure
- Respects all existing state file templates
- Maintains consistency with `quick_setup.py` workflow

**Template System**:
- Uses existing template system from `setup/templates/starter_packs/`
- Same template copying logic as `quick_setup.py`
- Supports all available templates (minimal, fantasy_adventure, etc.)

**Launcher Architecture**:
- Launcher → Bridge → TUI relationship unchanged
- RP creation happens before bridge starts
- New RPs fully initialized before launch

### Error Handling

- Duplicate RP name detection and user prompt to retry
- Template not found handling (uses basic structure)
- RPInitializer exceptions caught and displayed
- Template copy errors logged but don't block creation
