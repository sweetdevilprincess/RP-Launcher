# Changelog - 2025-10-17 - Version 1.1.0

**Release Date**: October 17, 2025
**Previous Version**: 1.0.1 (Documentation suite)
**Current Version**: 1.1.0

---

## Summary

Major proxy infrastructure refactoring: Created unified `ProxyClient` module that centralizes all proxy routing logic. This architectural improvement makes it trivial to add support for new LLM APIs (GPT-4, Gemini, Llama, etc.) with instant proxy support. Fixed critical bug where proxy settings weren't persisting. Simplified proxy UI and added comprehensive 3-stage proxy testing.

Improved bridge shutdown behavior: Implemented graceful agent shutdown with 60-second timeout to prevent data loss. Bridge now waits for background agents to complete their work before closing, with real-time countdown display. Added psutil dependency for reliable parent process monitoring.

**This is a MINOR version** because it adds significant new infrastructure, improves extensibility for multi-LLM support, and includes breaking changes to internal API signatures (but maintains backward compatibility for end users).

## Added

### Unified Proxy Client Module

**`src/clients/proxy_client.py`** (NEW MODULE)

Created dedicated proxy client that all LLM clients can use for consistent proxy routing:

**New Functions**:
- `load_proxy_config(rp_dir)` - Shared proxy configuration loader
  - Checks environment variables (`PROXY_URL`, `PROXY_TOKEN`)
  - Checks `config.json` with full hierarchy
  - Supports legacy field names (`ANTHROPIC_PROXY_URL/TOKEN`)
  - Returns dict: `{proxy_url, proxy_token, use_proxy}`

**New Class: `ProxyClient`**:
```python
proxy = ProxyClient(rp_dir)
response = proxy.post(url, headers, json, timeout)
# Automatic proxy routing - no manual logic needed
```

**Key Features**:
- `__init__(rp_dir)` - Auto-loads proxy config on initialization
- `post(url, headers, json, timeout, **kwargs)` - Drop-in replacement for `requests.post()`
  - Automatically replaces endpoint URL with proxy URL when enabled
  - Automatically adds `X-Proxy-Authorization: Bearer {token}` header
  - Mimics `requests.post()` API for easy integration
- `is_enabled()` - Check if proxy is currently active

**Architecture Benefits**:
- **Zero code duplication** - Proxy logic in one place
- **Instant multi-LLM support** - New LLM clients get proxy support automatically
- **Consistent behavior** - All LLMs route through proxy identically
- **Easy maintenance** - Add features (logging, retries) once, all clients benefit

**SillyTavern-Style Proxy**:
- Proxy URL replaces API endpoint (not HTTP traffic routing)
- Proxy token authenticates with proxy server
- Proxy forwards authenticated requests to real LLM services

### DeepSeek Client - Proxy Refactoring

**`src/clients/deepseek.py`** (REFACTORED)

Completely refactored to use new `ProxyClient` wrapper:

**Removed** (43 lines of manual proxy logic):
- `_load_proxy_settings()` function (now in `proxy_client.py`)
- Manual endpoint replacement logic
- Manual `X-Proxy-Authorization` header building
- `proxies` dict for HTTP traffic routing (incorrect approach)
- `proxy_url` and `proxy_token` function parameters

**Changed**:
```python

                  timeout, proxy_url, proxy_token):

    if use_proxy and proxy_url:
        endpoint = proxy_url
    headers["X-Proxy-Authorization"] = f"Bearer {proxy_token}"
    proxies = {"http": proxy_url, "https": proxy_url}
    response = requests.post(endpoint, headers, json, timeout, proxies)

# After (ProxyClient automatic handling)
def call_deepseek(prompt, rp_dir, model, temperature, endpoint, timeout):
    proxy = ProxyClient(rp_dir)
    response = proxy.post(endpoint, headers, json, timeout)
    # Proxy routing happens automatically
```

- Reduced code from ~43 lines to 2 lines
- Eliminated error-prone manual logic
- Consistent with other LLM clients
- Ready for multi-LLM expansion

## Fixed

### Critical: Proxy Settings Not Persisting

**`src/rp_client_tui.py` - Settings Screen** (BUG FIX)

Fixed critical bug where proxy settings appeared to save but weren't actually persisted:

**Root Cause**:
- SettingsScreen was saving to: `rp_dir.parent / "config" / "config.json"`
  - Resolved to: `RPs/config/config.json` (wrong location)
- Bridge was reading from: `base_dir / "config" / "config.json"`
  - Resolved to: `{project_root}/config/config.json` (correct location)
- Settings were being written to non-existent location

**Fix Applied**:
```python
# Before
def __init__(self, rp_dir: Path):
    self.config_file = rp_dir.parent / "config" / "config.json"  # Wrong

# After
def __init__(self, rp_dir: Path):
    base_dir = Path(__file__).parent.parent
    self.config_file = base_dir / "config" / "config.json"  # Correct
```

**Impact**:
- All proxy settings (URL, token, enabled) now persist correctly
- Settings screen and bridge now read/write same file
- Users no longer lose proxy configuration on restart

## Technical Details

### Proxy Routing Architecture

**SillyTavern-Style Proxy** (NOT HTTP Proxy):

Traditional HTTP Proxy (OLD approach - REMOVED):
```
Client → Set proxies={"http": proxy_url} → System routes HTTP through proxy
```

SillyTavern-Style Proxy (NEW approach):
```
Client → Replace endpoint URL with proxy URL → Proxy forwards to LLM
Client → Add X-Proxy-Authorization header → Proxy authenticates request
```

**How It Works**:
1. ProxyClient checks if proxy is enabled
2. If enabled: Replaces target endpoint with proxy URL
3. Adds `X-Proxy-Authorization: Bearer {token}` header
4. Proxy server receives request
5. Proxy authenticates via token
6. Proxy forwards request to actual LLM service
7. Proxy returns response to client

**Benefits**:
- Works with any proxy supporting bearer token auth
- Proxy can route to multiple LLM services
- Single proxy token for all LLMs
- Clear separation: client auth vs proxy auth

### Configuration Hierarchy

**Proxy Settings Load Order**:
1. Environment variables: `PROXY_URL`, `PROXY_TOKEN`
2. Global `config.json`: `proxy_url`, `proxy_token`, `use_proxy`
3. Legacy environment: `ANTHROPIC_PROXY_URL`, `ANTHROPIC_PROXY_TOKEN`
4. Legacy config: `anthropic_proxy_url`, `anthropic_proxy_token`

**Priority**: Earlier sources override later ones

**Example**:
```python
# Environment variable takes precedence
export PROXY_URL="https://proxy1.com"

# This is ignored because env var exists
config.json: {"proxy_url": "https://proxy2.com"}

# Result: Uses https://proxy1.com
```

### Error Handling

**Proxy Test Validation**:
- **Stage 1 Failure**: Connection refused, DNS error, timeout
- **Stage 2 Failure**: Authentication rejected (401/403)
- **Stage 3 Failure**: Routing issue, payload rejected

**Call Failures**:
- If proxy fails, original API error bubbles up
- No silent failures - errors are explicit
- Timeout handled per-request

```python
# src/clients/new_llm_client.py
from .proxy_client import ProxyClient

def call_new_llm(prompt, api_key):
    proxy = ProxyClient()
    headers = {"Authorization": f"Bearer {api_key}"}
    payload = {"prompt": prompt}
    response = proxy.post(
        "https://api.newllm.com/v1/completions",
        headers=headers,
        json=payload,
        timeout=60
    )
    return response.json()["result"]
```

That's it - instant proxy support!
