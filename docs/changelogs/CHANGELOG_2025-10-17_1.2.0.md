## Summary

Major new feature: Complete Session Log-Based Checkpoint & Retry System. This system allows users to:
- Retry responses they don't like (undo last response)
- Create named branches to explore different story paths
- Save checkpoints at important points
- Switch between different story timelines
- Search sessions by tags

The system uses JSON session logs as the single source of truth, replacing the need to modify chapter markdown files. All retry/branch/checkpoint operations are built on a single core operation (`copy_session()`), making the architecture elegant and maintainable.

**This is a MINOR version** because it adds a significant new feature system with new commands, new file structures, and comprehensive testing infrastructure, but maintains backward compatibility.

**Architecture Shift**: Session logs (JSON) become the primary data store, with chapter files becoming optional export format.

## Added

### Session Management System

**Core Module**: `src/session_manager.py` (NEW - 600+ lines)

Implemented complete session log system with the following capabilities:

**New Class: `SessionManager`**

A comprehensive manager for session-based story checkpoint and retry functionality.

**Key Methods**:
```python
# Core operation (powers all features)
copy_session(up_to_response, new_name, session_type, tags)

# Command implementations
retry(tags=None)                    # Undo last response
branch(name, response_num, tags)    # Create named branch
checkpoint(name, tags)              # Save checkpoint
switch(session_name)                # Switch active session
list_sessions(tag_filter)           # List/search sessions

# Message management
append_message(user_msg, assistant_resp, agent_data)
update_message_agent_data(response_num, field, data)
```

**Architecture Benefits**:
- **Unified operation**: All features use same `copy_session()` core
- **Single source of truth**: Session JSON contains everything
- **Atomic operations**: No partial failures
- **Agent data embedded**: No separate cache files to sync
- **Natural branching**: Copy session = create timeline

**Session Log Format** (JSON):
```json
{
  "session_id": "main",
  "session_type": "active",
  "current_response": 45,
  "tags": ["main-timeline"],
  "messages": [
    {
      "response_num": 1,
      "user_message": "...",
      "assistant_response": "...",
      "agent_data_background": {},
      "agent_data_immediate": {},
      "model_info": {}
    }
  ]
}
```

**File Structure Created**:
```
<RP_DIR>/sessions/
├── session_main.json           # Active session (PRIMARY)
├── branches/
│   ├── session_romance.json
│   └── session_action.json
```

## Architecture

### Session Log Architecture

**Key Insight**: Retry, branching, and checkpointing are **the same operation** - copying a session up to a specific response number.

**Before** (Old approach - chapter file modification):
```
Problem: Need to modify markdown files
- Parse chapter markdown
- Remove response blocks
- Update file structure
- Risk of corruption
- Complex text manipulation
```

**After** (Session log approach):
```
Solution: Copy JSON arrays
- Load session JSON
- Slice messages array
- Save to new file
- Simple, safe, atomic
```

**Core Operation**:
```python
def copy_session(up_to_response, new_name, tags):
    active = load_session("session_main.json")
    new_session = {
        ...
        "messages": active["messages"][:up_to_response]
    }
    save_session(new_session, f"sessions/{type}/{name}.json")
```

**All Commands Built On This**:
- `retry()` = `copy_session(current-1, "retry_TIMESTAMP", ["retry"])`
- `branch()` = `copy_session(N, name, ["branch"])`
- `checkpoint()` = `copy_session(current, name, ["checkpoint"])`

**Benefits**:
- ✅ Single source of truth (session JSON)
- ✅ TUI reloads session (no "erasing" needed)
- ✅ All features use same core operation
- ✅ Agent data embedded (no sync issues)
- ✅ Natural branching model
- ✅ Atomic operations (no partial failures)
- ✅ Simple to understand and maintain
